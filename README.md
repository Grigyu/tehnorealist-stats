# Серверный сбор статистики (GitHub Actions) — без вашего компьютера

Здесь сбор идёт **на сервере GitHub**, а сайт gromrez.ru просто читает готовый JSON. Ваш компьютер и браузер в цепочке не участвуют.

```
GitHub Actions (каждый час в :05)
   ├─ VK API            ─┐
   ├─ Дзен (API)         │
   ├─ Rutube API         ├─► data/stats.json ──► сайт gromrez.ru
   ├─ TenChat (страница) │      (в репозитории)     забирает JSON
   ├─ Telegram (t.me)    │                          и показывает цифры
   └─ сайты (HTTP)      ─┘
```

## Что нужно сделать один раз (10 минут)

1. **Создать репозиторий** на GitHub: например `tehnorealist-stats`, **публичный**
   (в нём только цифры, секретов нет; публичный нужен, чтобы страница могла читать JSON).
2. **Загрузить содержимое этой папки** в репозиторий (Add file → Upload files;
   структура должна сохраниться: `.github/workflows/stats.yml`, `collect/`, `web/`, `data/`).
3. **Добавить секрет** с токеном VK: Settings → Secrets and variables → Actions →
   New repository secret → имя `VK_TOKEN`, значение — ваш токен VK
   (тот, что лежит в проекте в `ВК/!.txt`).
4. **Включить Actions**: вкладка Actions → «I understand my workflows, go ahead and enable them».
5. **Запустить вручную первый раз**: Actions → stats → Run workflow (кнопка).
   Через минуту в репозитории появятся обновлённые `data/stats.json` и `web/index.html`.
6. **Вписать адрес данных**: откройте `web/remote_url.txt` и укажите свою ссылку:
   `https://raw.githubusercontent.com/<ваш-логин>/tehnorealist-stats/main/data/stats.json`
   Затем Actions → Run workflow ещё раз (пересоберёт страницу с этим адресом).
7. **Залить страницу на хостинг**: скачать из репозитория `web/index.html` и положить
   на gromrez.ru в папку (например `/stat/`). Это единственная заливка — дальше страница
   сама подтягивает свежий JSON каждый час.

## Что происходит дальше

- Каждый час в :05 GitHub запускает сбор, коммитит новый снимок, история растёт.
- Страница на gromrez.ru при открытии забирает JSON и показывает актуальные цифры,
  историю и время снимка. Если GitHub недоступен — показывает последние вшитые данные.

## Telegram

Раньше Telegram не работал, потому что с вашей машины `t.me` закрыт по IP.
Серверы GitHub находятся вне этого ограничения, поэтому `t.me` открывается и
цифры каналов попадают в отчёт автоматически — без VPN и без вашего участия.
Если когда-нибудь и там закроют, в таблице будет «нет доступа» и последнее значение с датой.

## MAX

MAX отдаёт число подписчиков только владельцу в приложении — публичного API нет.
Поэтому MAX берётся из `collect/authorized_values.json` (сейчас 64, с датой и скриншотом).
Обновлять можно двумя способами:

- с вашего компьютера, когда открыт браузер с профилем: `python _tools\cdp_collect_max.py`,
  затем закоммитить `collect/authorized_values.json`;
- либо раз в день вручную: скриншот + правка одной строки в этом файле.

## Проверить локально (без GitHub)

```
python collect/collect_stats.py          # снимок в data/stats.json
python web/build.py                      # страница
```

VK-токен берётся из переменной окружения `VK_TOKEN`, если она задана; иначе — из `ВК/!.txt`.


## MAX: серверное чтение (сделано 30.10.2026)

MAX отдаёт данные только авторизованной сессии, но сессия переносится токеном.
Проверено: чистый браузер без вашего профиля, с одним токеном, открывает канал
и показывает число подписчиков.

В репозиторий добавлены:

- `tools/max_collect.py` — Chromium (Playwright) с подстановкой токена в localStorage;
- шаг в workflow: если секрет `MAX_AUTH` задан, MAX читается на сервере каждый час,
  скриншот и значение коммитятся в репозиторий.

### Что добавить в секреты (Settings → Secrets → Actions)

Файл `MAX_SECRET.txt` в этой папке (в репозиторий не попадает — он в .gitignore):

| Имя секрета | Значение |
|---|---|
| `MAX_AUTH` | строка из файла, после `MAX_AUTH=` (это JSON целиком) |
| `MAX_DEVICE_ID` | строка после `MAX_DEVICE_ID=` |
| `MAX_CHANNEL_URL` | необязательно; по умолчанию адрес канала из файла |

Профиль браузера кэшируется между запусками (`actions/cache`), поэтому вход
выполняется один раз, а не каждый час. Первый запуск MAX регистрируется в приложении
как новое устройство — это ожидаемо; в настройках MAX это видно и отменяется.

### Если токен перестанет работать

Сессия живёт долго, но при смене пароля или выходе из всех устройств токен умирает.
Тогда: открыть MAX в браузере с профилем, снова выполнить `python _tools\cdp_collect_max.py`
(он обновит `collect/authorized_values.json`), а строку `MAX_AUTH` обновить из консоли
браузера: `localStorage.getItem('__oneme_auth')`.
